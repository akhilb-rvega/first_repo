NV_NVDLA_BDMA_zero_detector (8-bit, per-beat version)

Objective

Implement a synthesizable SystemVerilog module named:

NV_NVDLA_BDMA_zero_detector

This module implements a per-beat zero-detection engine that operates as a lightweight pre-processing stage in the NVDLA BDMA data path for sparse compression and metadata generation. The design is fully synchronous, deterministic, and synthesizable.

1. High-Level Functional Description
1.1 Proposal Overview

The Zero Detector Engine provides beat-level sparsity awareness in the NVDLA BDMA data path. Each incoming 8-bit data beat is inspected independently to determine whether it is zero. The result is emitted as metadata alongside the data stream and may be consumed by downstream sparse compression, skipping, or routing logic.

This implementation intentionally avoids internal beat counting and block accumulation. Each beat is treated as an independent detection unit, simplifying control logic and eliminating block-level state.

1.2 Purpose

The purpose of this module is to:

Identify zero-valued data beats early in the data-movement pipeline

Generate per-beat zero metadata with minimal latency

Preserve full throughput under backpressure

Enable downstream logic to aggregate beats into blocks if required

This approach improves flexibility and reduces hardware complexity while remaining compatible with sparse compression pipelines.

1.3 Solution Architecture

The solution is a Moore-FSM–driven, streaming zero-detection engine that:

Inspects each 8-bit input beat

Determines whether the beat is zero

Emits a 1-bit zero indicator per accepted beat

Passes data through transparently with valid/ready flow control

Supports dynamic bypass

No internal beat counter, block boundary tracking, or overflow detection is implemented in this version.

1.4 Implementation Scope

The RTL implementation is intentionally minimal and robust:

No counters

No multi-beat accumulation

No overflow conditions

Deterministic recovery on disable

Block-level semantics, if required, are expected to be implemented downstream.

3. Functional Requirements
3.1 Zero Detection Logic

Beat-Level Detection: For each 8-bit input word, determine if the value is zero

Independent Beats: No accumulation across beats

Result Generation: One zero-detection result per accepted beat

3.2 Block Size Configuration

cfg_block_size is not used

No beat counting

No block boundary detection

3.3 State Machine (FSM)

States: IDLE, DONE

IDLE: Wait for an input beat

DONE: Hold zero-detection result until accepted

FSM behavior is fully synchronous and deterministic.

3.4 Data Path

Bypass Mode (cfg_enable = 0)

Data passes through combinationally

No zero-detection metadata generated

Enabled Mode

1-cycle registered data path

Full valid/ready backpressure support

3.5 Zero Result Handshake

Zero-detection result uses an independent valid/ready channel

Exactly one metadata result per accepted data beat

Result is cleared once accepted

3.6 Error Handling

No overflow or error conditions

Error output permanently deasserted

Disabling zero detection clears all internal state

4. Timing and Latency
4.1 Data Path Latency

4.2 Zero Result Timing

Result persists until handshake completes

8. Impact Description

This 8-bit per-beat zero detector provides fine-grained sparsity metadata with minimal hardware overhead. It simplifies control logic, improves timing closure, and enables downstream engines to implement flexible block-level sparse optimizations without constraining the BDMA datapath.

9. Success Criteria (Updated)

Implementation is correct if:
